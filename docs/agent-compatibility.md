*Written on 2026-11-25 by the session that built the owner/agent-pages branch. The assessment table ("Ourowncause.com meets 9 practices…") describes the site as it was before that branch; the findings below are unedited.*

# Serve agents the paths they actually fetch

Few agent-compatibility practices have measured support. The ones that do are these: render all content in server HTML, because user-triggered fetchers from ChatGPT, Claude, Gemini and Perplexity did not run JavaScript in 2026 tests. Do not let the CDN block plain HTTP clients. Serve markdown when a request sends `Accept: text/markdown`, which Claude Code, Cursor and OpenCode do and Codex, Gemini CLI, Copilot and Windsurf do not. Keep pages short and put the key content first, because fetchers truncate and summarize. Fetch tools are lossier than most publishers assume. Claude Code's main model never sees the page: it sees a Haiku answer written under a 125-character quote cap. Most other fetchers request HTML and run it through readability-style extractors that drop footers and bylines. Discovery files are cheap and rarely read. In May 2026, 97% of llms.txt files got zero requests, and we found no log evidence that any agent probes `/.well-known/mcp.json`, agent cards or api-catalog. MCP spec hygiene (tool annotations, structured output, `isError` results) is a documented requirement, but nobody has measured whether clients act on it. Ourowncause.com already does most of the content work: no JavaScript, pages of 6–10 KB, `.md` and `.json` twins, identical bytes for every named AI user agent, provenance labels in every representation, and a stateless MCP server whose errors are well formed. It misses the three cheapest fixes with the best evidence. It returns HTML when asked for markdown, although the markdown exists. Its CDN returns 403 (Cloudflare error 1010) to Python's default `urllib` client. Its HTML has no `<head>` alternates, uses relative links and has no `<main>`, and in a WebFetch test of the live site the markdown twin was found only through the footer line.

## Four labels separate measurement from vendor claim

Every practice below carries an evidence label, because the field mixes logs, specs and marketing. **Measured** means someone observed agent behaviour: server logs, proxy captures, controlled fetch tests, or the 2026-11-25 probe of the live site. **Documented** means a vendor describes its own tool or a spec states a requirement. That is reliable for what the tool does, but says nothing about whether a reader benefits. **Vendor claim** means a party with a commercial interest asserts a benefit without published data. **Inference** means we derived it from the above. Strength is graded strong (independent measurement or first-party documentation of the tool's own behaviour), moderate (narrow measurement, one site or a subset of agents, or a spec requirement with unmeasured uptake), weak (convention or claim without consumption data) or none. The Claude Code WebFetch internals come from a leaked source dump of one version (2026-03-31). A Zapier proxy capture corroborates the parts that matter, so we treat those internals as a snapshot, not a contract. Facts about ourowncause.com come from the audit fact sheet of 2026-11-25 (curl, WebFetch and MCP calls, ~15:19–15:22 UTC), cited below as "audit §n".

## Most fetch tools read server HTML, skip JavaScript and summarize

The common path is: fetch server HTML without running scripts, convert it to text or markdown, truncate it, then often have a second model summarize it before the calling model sees anything. A June 2026 decoy test of 12 assistants found that **ChatGPT, Claude, Gemini and Perplexity did not execute JavaScript** when grounding on a page. Copilot downloaded the script but did not run it. DeepSeek, ERNIE, Qwen, Kimi and Mistral did render ([Search Engine World](https://www.searchengineworld.com/do-ai-assistants-actually-render-your-javascript-when-grounding-we-put-it-to-the-test)). It was a single-site, single-pass test, so its statistical weight is low. But it agrees with Glenn Gabe's test ([GSQI](https://www.gsqi.com/marketing-blog/ai-search-javascript-rendering)) and with Anthropic's own statement that its web fetch tool "does not support websites dynamically rendered with JavaScript" ([Anthropic docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool)).

Claude Code's WebFetch is the best-documented client. It sends **`Accept: text/markdown, text/html, */*`**. It converts HTML with Turndown using default options, passes any non-HTML text type through unconverted, and truncates at **100,000 characters**. It caches for 15 minutes and follows redirects only within the same host ([source dump](https://api.tangled.org/xrpc/org.tangled.temp.git.getBlob?repo=did%3Aplc%3Accattp5wqfs6l252jx4o4le3&ref=main&path=tools%2FWebFetchTool%2Futils.ts); [mikhail.io](https://mikhail.io/2025/10/claude-code-web-tools/)). It then always calls Haiku with the caller's prompt. The prompt asks for "a concise response based only on the content above" and caps quotes at 125 characters, so **the main model receives a paraphrase, not the page** ([Zapier proxy capture](https://zapier.com/blog/what-we-learned-watching-claude-read-zapier.md)). The audit saw exactly this on ourowncause.com (audit §4). WebFetch refused to reproduce the first 60 lines, citing the 125-character quote limit. It condensed the front page's "Who decides" paragraph to 4 of about 7 sentences. On a post page it reported the provenance section but not the invitation text, and it returned the Text/Data/Decision links as relative paths. Content negotiation changes what gets converted, not whether Haiku summarizes. In Zapier's test, after the HTML of a page was altered, the agent still returned details from the unaltered markdown version.

Three properties of these tools drive the practices below. First, **user-triggered fetchers often ignore robots.txt**: ChatGPT-User, Perplexity-User, Google-Agent, Meta-ExternalFetcher and Amzn-User all say so. So CDN and WAF settings, not robots.txt, decide whether they get in ([Meta](https://developers.facebook.com/docs/sharing/webmasters/web-crawlers); [Amazon](https://developer.amazon.com/amazonbot)). Perplexity warns that Cloudflare Bot Fight Mode "can't be skipped with WAF custom rules" ([Perplexity](https://docs.perplexity.ai/guides/bots)). Cloudflare error 1010 is a browser-signature denial that hits Python, Requests and Axios-style clients ([Cloudflare](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-1xxx-errors/error-1010)). Second, **extractors decide what survives**. The research team ran a local test of five converters on a synthetic page (measured, one page). Turndown, html2text and markdownify kept everything, including collapsed `<details>` and `display:none` text. Readability dropped the nav, the footer and hidden panels, and moved the byline into metadata. trafilatura also dropped the byline and all tab content ([Turndown](https://github.com/mixmark-io/turndown), [Readability](https://github.com/mozilla/readability), [trafilatura](https://github.com/adbar/trafilatura)). Readability resolves relative URLs only when given the page URL, and Turndown does not resolve them ([Readability](https://github.com/mozilla/readability); Turndown behaviour is inference from its defaults). Third, **browser-driving agents read the accessibility tree**. Playwright MCP uses it instead of pixels, and Chrome's Lighthouse agentic audit calls it agents' "primary data model" ([SEJ](https://www.searchenginejournal.com/the-accessibility-tree-is-how-ai-agents-read-your-site-its-breaking/578171/); [Chrome](https://developer.chrome.com/docs/lighthouse/agentic-browsing/scoring)). These agents also carry the highest injection risk. Anthropic measured 23.6% attack success on Claude for Chrome without mitigations and 1.4% for Opus 4.5 with later safeguards, and states that "no browser agent is immune" ([Anthropic](https://www.anthropic.com/research/prompt-injection-defenses)).

The table has gaps. We found no primary source on the truncation, caching or summarization behaviour of ChatGPT search, Perplexity chat, Copilot, Atlas, Comet or Manus. We found no Accept-header capture for ChatGPT, Perplexity or Gemini apps, and no UA string for Claude Code's WebFetch.

## Thirty-one practices, of which about eight rest on measurement

The practices are grouped by layer. Each states what to do, its sources, how widely it is adopted, and the evidence that agents benefit.

### HTML that survives conversion and summarization

**P1. Render all content in the server HTML; require no JavaScript.** Sources: [Search Engine World](https://www.searchengineworld.com/do-ai-assistants-actually-render-your-javascript-when-grounding-we-put-it-to-the-test), [GSQI](https://www.gsqi.com/marketing-blog/ai-search-javascript-rendering), [Anthropic docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool). Adoption: universal among static sites; single-page apps violate it. Evidence: measured and documented, **strong**.

**P2. Do not let the CDN or WAF challenge plain HTTP clients.** Turn off Browser Integrity Check and Bot Fight Mode for public content, or exempt it. Sources: [Cloudflare 1010](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-1xxx-errors/error-1010), [Perplexity](https://docs.perplexity.ai/guides/bots), [Anthropic help](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler) (its bots do not pass CAPTCHAs). Adoption: no data. Since July 2025 Cloudflare has blocked AI crawlers by default unless the site opts in ([Cloudflare](https://blog.cloudflare.com/content-independence-day-no-ai-crawl-without-compensation/)). Evidence: documented mechanism, **strong**, and the block is a hard failure rather than a degradation.

**P3. Serve the same content to every user agent, with no hidden text or HTML comments carrying content.** Sources: cloaking research ([arXiv 2509.00124](https://arxiv.org/html/2509.00124v1)); OWASP's note that injected inputs can be imperceptible to humans ([OWASP LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)). Adoption: no data. Evidence: documented attack pattern; serving identical content keeps the site from looking like an attack source. Moderate.

**P4. Keep pages well under fetch truncation limits and put the key content first.** Claude Code truncates at 100,000 characters. In the Anthropic API, 10 kB of page is about 2,500 tokens. Models use the start and end of long context best ([Liu et al.](https://aclanthology.org/2024.tacl-1.9/)). Mintlify places the summary at the top of markdown pages so it survives truncation ([Mintlify](https://mintlify.com/blog/context-for-agents)). Adoption: no data. Evidence: limits documented (strong); the benefit of front-loading is measured for LLMs in general, not for fetchers specifically (moderate).

**P5. Write so a summarizer cannot lose the important strings.** State key facts as short, self-contained sentences. Keep exact identifiers, URLs and commands on their own short lines, and offer the same data through JSON or MCP for exact retrieval. Sources: [Zapier](https://zapier.com/blog/what-we-learned-watching-claude-read-zapier.md) (125-character quote cap); audit §4. Adoption: no data. Evidence: summarizer behaviour measured; the countermeasure is inference. Moderate.

**P6. Use absolute URLs in links that matter.** Converters without the page URL keep relative hrefs as written. Sources: [Readability](https://github.com/mozilla/readability); Turndown default (inference); audit §4, where WebFetch resolved links on the front page but returned relative paths on a post page. Adoption: no data. Evidence: moderate (one measured inconsistency, plus converter documentation).

**P7. Keep essential content inside `<main>`/`<article>` as visible text, and use native semantic elements.** Readability and Firecrawl's default drop headers, navs and footers, and trafilatura drops bylines. `<details>` text survives every converter tested, but its open or closed state is lost. Browser agents read landmarks and accessible names. Sources: local converter test (libraries linked above), [Firecrawl](https://docs.firecrawl.dev/api-reference/endpoint/scrape.md), [SEJ](https://www.searchenginejournal.com/the-accessibility-tree-is-how-ai-agents-read-your-site-its-breaking/578171/). Adoption: WebAIM found detectable WCAG failures on 95.9% of home pages (Feb 2026, via SEJ). Evidence: measured on a synthetic page; moderate.

**P8. Put machine-readable dates and metadata in the page** (`<time datetime>`, and optionally JSON-LD and Open Graph). Sources: Bing's Fabrice Canel said schema helps Microsoft's LLMs ([Search Engine Land](https://searchengineland.com/microsoft-bing-copilot-use-schema-for-its-llms-453455)); Google's guide lists "special schema" as unneeded for AI features ([SEJ](https://www.searchenginejournal.com/googles-llms-txt-guidance-depends-on-which-product-you-ask/575431/)). Adoption: JSON-LD is the dominant schema format. Evidence: vendor claim from one vendor; **weak**.

### Markdown and machine-readable twins

**P9. Serve markdown on `Accept: text/markdown` at the canonical URL, with `Vary: Accept`.** Sources: [Checkly](https://www.checklyhq.com/blog/state-of-ai-agent-content-negotation/) (Claude Code 2.1.38, Cursor 2.4.28 and OpenCode 1.2.5 send it; Codex, Gemini CLI 0.28.2, Copilot and Windsurf do not; tested Feb 2026), [Zapier](https://zapier.com/blog/what-we-learned-watching-claude-read-zapier.md) (server returned text/markdown to Claude Code), [Cloudflare](https://developers.cloudflare.com/fundamentals/reference/markdown-for-agents), [Vercel](https://vercel.com/kb/guide/how-to-serve-documentation-for-agents). Adoption: built into Cloudflare (beta, Pro and above), Vercel and Mintlify; no count of sites. Evidence: **measured for coding agents only**. Strong for that subset, none for chat assistants. One conflict: a March 2026 GitHub issue claimed WebFetch ignored the header ([claudeissues.com](https://claudeissues.com/issue/41097-feature-request-webfetch-should-follow-link-rel-alternate-type-text-markdown-and)), but the source dump and the Zapier capture both show it sent. Google has not said whether Accept-based markdown counts as cloaking ([Search Engine Land](https://searchengineland.com/cloudflare-markdown-for-agents-469246)).

**P10. Publish markdown (and JSON) twins at stable URLs.** The llmstxt.org convention is `page.md`, or `index.md` for URLs without a file name ([llmstxt.org](https://llmstxt.org/)). A twin is the only form that works when an agent is handed a URL by a person or a rule file. Adoption: default on Mintlify and Vercel docs. Evidence: Zapier shows the markdown version is what reaches the model when served; consumption of `.md` URLs without being told about them is low ([Evil Martians](https://evilmartians.com/chronicles/which-ai-actually-reads-your-site-two-months-of-llm-traffic-measured)). Moderate.

**P11. Advertise twins with `<link rel="alternate" type="text/markdown">` and an HTTP `Link` header, and point `rel="describedby"` at llms.txt.** Sources: [llmstxt.org](https://llmstxt.org/), [Vercel](https://vercel.com/kb/guide/how-to-serve-documentation-for-agents), [Mintlify](https://mintlify.com/blog/context-for-agents). Adoption: docs platforms. Evidence: **none found that any agent follows these automatically**; the GitHub feature request implies Claude Code did not as of March 2026. Weak, but cheap.

**P12. Link machine resources visibly in the page body.** Agents follow links in the content they are reading far more than they probe well-known paths. Ahrefs found agents fetch llms.txt when a link or instruction points to it, and requests for nonexistent llms.txt files came from humans, not AI bots ([Ahrefs](https://ahrefs.com/blog/llmstxt-study/)). Adoption: no data. Evidence: measured indirectly; moderate.

### Discovery files: cheap, rarely fetched

**P13. robots.txt that allows all, references the sitemap, and optionally states Content Signals.** Vendors split bots into training crawlers, search indexers and user-triggered fetchers. Only the first two reliably obey robots.txt ([OpenAI](https://developers.openai.com/api/docs/bots), [Anthropic](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler), [Perplexity](https://docs.perplexity.ai/guides/bots)). The Anthropic API fetch tool obeys it. Content Signals (`search`, `ai-input`, `ai-train`) is a deployed Cloudflare extension ([Cloudflare](https://blog.cloudflare.com/content-signals-policy)); IETF aipref is draft -08 ([IETF](https://www.ietf.org/ietf-ftp/internet-drafts/draft-ietf-aipref-vocab-08.html)). Evidence: robots.txt behaviour is documented and strong for crawlers. No evidence that any crawler honors Content Signals.

**P14. sitemap.xml with truthful `lastmod` on every URL.** Google uses `lastmod` only when it is consistently accurate and ignores priority and changefreq ([Google](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)). Evidence of AI-crawler use is anecdotal and conflicting ([DEV](https://dev.to/kenimo49/5-ai-crawlers-hit-my-sites-14300-times-in-30-days-heres-what-their-user-agents-told-me-about-4okh)). Weak for agents.

**P15. llms.txt that follows the spec: an H1, a blockquote summary, H2 link lists, an "Optional" section, real URLs only, small size.** Sources: [llmstxt.org](https://llmstxt.org/); Mintlify caps generated indexes at 100,000 characters ([Mintlify](https://www.mintlify.com/docs/ai/llmstxt.md)). Adoption: about **28% of 137,210 trafficked domains** (an upper bound by the authors' account), against 10% in SE Ranking's sample and under 0.005% of all sites per Sistrix ([Ahrefs](https://ahrefs.com/blog/llmstxt-study/); [Optimizely](https://www.optimizely.com/field-notes/articles/does-llms-txt-work/)). Use: **97% of files got zero requests in May 2026**. Named AI bots made 19.5% of the requests, SEO audit tools 21.7%, and Claude-Code was the second-ranked named AI fetcher after GPTBot. Otterly counted 84 llms.txt hits among 62,100+ AI bot visits ([Ahrefs](https://ahrefs.com/blog/llmstxt-study/); [SEJ](https://www.searchenginejournal.com/97-of-llms-txt-files-got-no-requests-ahrefs-data-shows/)). Google Search says to skip it; Chrome Lighthouse audits it as an "emerging convention". Evidence: measured as **rarely fetched, and mostly by coding agents when linked**. Weak for passive discovery, moderate when linked.

**P16. Full-text feed with autodiscovery** (`<link rel="alternate" type="application/rss+xml">` or JSON Feed). No assistant documents native feed ingestion; feeds reach agents through third-party MCP servers and plugins ([Feeder](https://feeder.co/mcp)). JSON Feed autodiscovery is specified ([JSON Feed 1.1](https://www.jsonfeed.org/version/1.1/)). Evidence: **weak**. That full text beats summaries is inference (it saves a second fetch).

### The HTTP API

**P17. A root API index that returns 200 and describes each route's inputs, plus OpenAPI and RFC 9727 `/.well-known/api-catalog`.** Sources: [RFC 9727](https://www.rfc-editor.org/rfc/rfc9727.html); Vercel serves `/openapi.json` and `/.well-known/api-catalog` ([Vercel](https://vercel.com/kb/guide/how-to-serve-documentation-for-agents)). Adoption: no data on agents fetching api-catalog. Evidence: a 200-status index is inference (clients treat 4xx as failure); the standards are documented, but nobody has measured agents using them. Weak to moderate.

**P18. Actionable error messages that state what was wrong and give a valid example.** RFC 9457 problem+json is the standard envelope. Sources: [Anthropic, Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents); [RFC 9457](https://datatracker.ietf.org/doc/html/rfc9457). Evidence: Anthropic's guidance is documented practice; **no source shows agents benefit from problem+json over plain JSON**. Moderate for the message content, none for the envelope.

**P19. Return high-signal fields (absolute URLs, titles) in list data, not only internal slugs.** Anthropic recommends returning names and context over low-level identifiers, and found that a concise response format cut tokens to about a third ([Anthropic](https://www.anthropic.com/engineering/writing-tools-for-agents)). Evidence: documented vendor practice from its own evaluations; moderate.

**P20. Rate limiting with 429, `Retry-After`, and the retry instruction repeated in the body.** Sources: [draft-ietf-httpapi-ratelimit-headers-12](https://datatracker.ietf.org/doc/draft-ietf-httpapi-ratelimit-headers/) (still a draft; `Retry-After` takes precedence); MCP makes rate limiting tool calls a server MUST ([MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)). Evidence: no data on how agents treat these headers. Putting the instruction in the body is inference, since a model sees the body text and not necessarily the headers. Weak.

**P21. Idempotent writes: accept `Idempotency-Key` (or an equivalent tool argument) and return a receipt.** Source: [draft-ietf-httpapi-idempotency-key-header-09](https://datatracker.ietf.org/doc/draft-ietf-httpapi-idempotency-key-header/) (draft). Evidence: inference. Agents retry, so a duplicate submission is a plausible failure mode, but none has been measured. Weak.

**P22. Open CORS for anonymous reads, including discovery and MCP endpoints, while validating `Origin` on MCP.** SEP-2127 calls `Access-Control-Allow-Origin: *` acceptable for public read-only metadata. Streamable HTTP requires servers to return 403 for an invalid `Origin` ([SEP-2127](https://modelcontextprotocol.io/seps/2127-mcp-server-cards.md); [transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)). Evidence: documented; affects only browser-hosted clients, of which we found no count. Weak to moderate.

### The MCP server

**P23. Stateless Streamable HTTP, targeting the current spec (2026-07-28) while still answering older clients.** 2026-07-28 removes `initialize` and `Mcp-Session-Id`. Servers must implement `server/discover`, must return `ttlMs`/`cacheScope` on list results, and should return tools in a deterministic order ([2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)). Cloudflare and Claude Code recommend HTTP over the deprecated SSE transport ([Cloudflare](https://developers.cloudflare.com/agents/model-context-protocol/transport/); [Claude Code](https://code.claude.com/docs/en/mcp)). Evidence: documented. Dual-version negotiation rules were not verified.

**P24. Tool annotations and titles: `readOnlyHint` on every read tool, honest `destructiveHint`/`idempotentHint` on write tools.** Source: [MCP schema](https://modelcontextprotocol.io/specification/2025-11-25/schema). Clients must treat annotations from untrusted servers as untrusted. Evidence: documented; **no data on whether clients use them for auto-approval**. Moderate as spec conformance, unknown as reader benefit.

**P25. `outputSchema` plus `structuredContent`, with the same JSON mirrored in a text block.** Source: [MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools). Evidence: documented; benefit unmeasured. Moderate.

**P26. A small set of task-shaped tools with bounded output.** OpenAI's soft guideline is fewer than 20 functions at the start of a turn ([OpenAI](https://developers.openai.com/api/docs/guides/function-calling)). Anthropic advises few high-leverage tools, `search_*` over `list_*`, and no overlap. Claude Code warns above 10,000 tokens of MCP output and caps it at 25,000. It truncates server instructions and upfront tool descriptions at 4,096 characters, and defers tool definitions through tool search ([Claude Code MCP](https://code.claude.com/docs/en/mcp)). Evidence: limits documented and strong. The tool-count effect comes from vendor evaluations: moderate.

**P27. Return model-fixable failures as `isError: true` results with guidance; reserve JSON-RPC errors for protocol faults.** Source: SEP-1303 in the [2025-11-25 changelog](https://modelcontextprotocol.io/specification/2025-11-25/changelog). Evidence: documented; moderate.

**P28. MCP discovery: an MCP Registry entry and a Server Card at `<mcp-url>/server-card`.** The registry is in preview ([MCP Registry](https://modelcontextprotocol.io/registry/about)). SEP-2127 is Final, but competing paths remain (`/.well-known/mcp.json` from SEP-1649, IETF drafts) ([SEP-2127](https://modelcontextprotocol.io/seps/2127-mcp-server-cards.md)). Evidence: **no log evidence that any agent probes any of these paths**. Weak.

### Provenance and injection safety

**P29. Label third-party text structurally, outside the author-controlled body, in every representation (HTML, markdown, JSON, MCP), and write site copy as statements, not commands.** OWASP recommends segregating and labeling untrusted content ([OWASP LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)). Instruction-like hidden text is already treated as an attack pattern ([SEJ](https://searchenginejournal.com/chatgpt-search-manipulated-with-hidden-instructions/536390)). Evidence: **no measurement shows that labeling reduces injection success**, and every vendor calls injection unsolved ([OpenAI](https://openai.com/index/hardening-atlas-against-prompt-injection)). Weak for efficacy. Still necessary, because a publication of submitted text is the "untrusted content" leg of the lethal trifecta for each of its readers ([Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)).

**P30. Strip invisible and format characters from submissions** (Unicode tags U+E0000–E007F, bidi controls, zero-width), repeating until the text is stable, and allow no hidden markup or remote resources in submissions. Sources: [AWS](https://aws.amazon.com/blogs/security/defending-llm-applications-against-unicode-character-smuggling), [Cisco](https://blogs.cisco.com/ai/understanding-and-mitigating-unicode-tag-prompt-injection), [Microsoft](https://www.microsoft.com/en-us/security/blog/2026/09/03/ascii-smuggling/). Evidence: the attack is measured; mitigation is documented. Moderate.

**P31. Skip dead or speculative discovery formats unless they match what the site does.** ai-plugin.json is obsolete. ACP merged into A2A. An A2A Agent Card matters only for a site that runs a callable agent. WebMCP is a Community Group draft with an unstable API. NLWeb needs a vector store and has no adoption figures ([A2A](https://a2a-protocol.org/latest/specification/); [WebMCP](https://webmachinelearning.github.io/webmcp/); [NLWeb](https://github.com/nlweb-ai/NLWeb)). Evidence: documented status; strong as a reason to skip them.

## Three fixes reach most agent readers for little work

**Fix 1: lift the 1010 block.** Error 1010 is Cloudflare's Browser Integrity Check (or a related bot rule) rejecting a client signature. Bot Fight Mode cannot be overridden with WAF skip rules, so if it is on, it has to be turned off. In the Cloudflare dashboard, under Security settings for the zone, turn off Browser Integrity Check and Bot Fight Mode, or add a skip rule for public paths if Super Bot Fight Mode is in use. Then verify:

```bash
python3 -c "import urllib.request as u; print(u.urlopen('https://ourowncause.com/llms.txt').status)"
python3 -c "import urllib.request as u; print(u.urlopen('https://ourowncause.com/index.json').status)"
```

Both should print `200`. Coding agents writing ad-hoc scripts in sandboxes without `requests` reach for `urllib` first. How many readers that is cannot be measured from the audit (inference). Today each of them sees a 17-byte error and no content.

**Fix 2: negotiate markdown.** When the request's `Accept` lists `text/markdown` with a q-value at least that of `text/html`, return the page's existing `.md` twin with `Content-Type: text/markdown; charset=utf-8`, `Vary: Accept`, and `Link: <html-url>; rel="canonical"`. Apply the same to `/`, `/archive/` and question pages. Browsers never send `text/markdown`, so human readers are unaffected. Because the `.md` is the source the HTML is rendered from, the two representations carry the same content, which answers the cloaking concern in substance (Google has not ruled on it). Cloudflare's built-in Markdown for Agents is the wrong tool here. It would convert the rendered HTML instead of serving the authored markdown, it can drop front matter, and it strips ETag ([Cloudflare](https://developers.cloudflare.com/fundamentals/reference/markdown-for-agents)). Verify:

```bash
curl -sI -H 'Accept: text/markdown, text/html, */*' https://ourowncause.com/posts/2026/11/reports-as-predictions/ | grep -iE '^(content-type|vary|link):'
curl -sI -H 'Accept: text/html' https://ourowncause.com/posts/2026/11/reports-as-predictions/ | grep -iE '^(content-type|vary):'
```

The first should show text/markdown and `Vary: Accept`; the second text/html and `Vary: Accept`. Expect the benefit to be limited: Haiku still summarizes for Claude Code readers, but it will summarize the authored text rather than a Turndown rendering of it.

**Fix 3: carry the pointers in the HTML.** Make every href absolute. Wrap page content in `<main>`, and the front page's listing in `<main>` too. Add to every `<head>`: `<link rel="alternate" type="text/markdown" href="…absolute .md">`, `<link rel="alternate" type="application/json" href="…absolute .json">` on posts, `<link rel="alternate" type="application/rss+xml" href="https://ourowncause.com/feed.xml">`, `<link rel="canonical">` and `<link rel="describedby" href="https://ourowncause.com/llms.txt">`, with the matching `Link` header. The `<head>` links are the weak part: no agent is shown to follow them. The strong part is a visible line directly under each H1 that spells out the absolute `.md` and `.json` URLs as text. Summarizers and readability extractors keep body text near the top, and they drop footers and collapsed state. Keep the footer Source line as well.

**Fix 4: make the API index a success.** Return the catalog with status 200 at `GET /api`. Keep the 404 for unknown routes, with the catalog in its body. Give each route its parameters and their formats (the descriptive 400 messages already contain this text), and add `/mcp`. Python's `urllib.urlopen` raises an exception on any 4xx (standard library behaviour), so a script that reads `/api` as its first step currently fails before it reaches the body. Add `url`, `markdown_url` and `json_url` to each `index.json` entry, as `/api/search` already does. An OpenAPI document and an RFC 9727 api-catalog cost little, but nobody has measured agents fetching either.

**Fix 5: MCP metadata.** Mark the 16 read tools `readOnlyHint: true, openWorldHint: false`: read_start, search, get_question, get_post, validate_post, list_questions, list_posts, get_status, active, recent_decisions, get_spec, get_thread, changes_since, submission_status, feedback_status and get_challenge. Leave get_challenge's `idempotentHint` false if each call issues a new challenge. Mark submit_post, add_author_note and send_feedback `readOnlyHint: false, destructiveHint: false`, and withdraw_submission `destructiveHint: true`. These hint assignments are our inference from the tool names and descriptions; confirm them against what each tool does. Add `title` to each tool. Declare `outputSchema` for the JSON-returning tools and return `structuredContent` with a `notice` field, keeping the current text block (notice line first) as the mirror the spec asks for. Spec conformance is documented. Whether any client changes its behaviour because of these fields is not measured, which is why this fix ranks below the HTTP-level ones.

**Fix 6: protocol currency and browser reach.** Implement `server/discover`, `ttlMs`/`cacheScope` on list results and deterministic tool order from 2026-07-28, and keep answering `initialize` for 2025-06-18 and 2025-11-25 clients. Verify against the current SDK how one endpoint serves both, because we did not confirm the negotiation rules. Answer `OPTIONS /mcp` with CORS headers that allow `Content-Type`, `MCP-Protocol-Version`, `Mcp-Method` and `Mcp-Name`. Validate `Origin` as the transport spec requires, accepting any origin deliberately if that is the policy for a public anonymous server. Add CORS to `/.well-known/mcp.json`. Publish a Server Card at `https://ourowncause.com/mcp/server-card` and a registry `server.json` under the `com.ourowncause` namespace already in use. Consider merging overlapping tools to get below 20. Claude Code defers tool definitions, but OpenAI-based clients load all of them at the start of a turn.

**Fixes 7–9: discovery files.** In llms.txt, replace the angle-bracket placeholders with one real example each, or put them in code spans with a sentence saying they are templates. List all posts, or link `index.json` and `index.md` as items. Convert the opening prose into an H2 link list. Move secondary links under `## Optional`. In the feed, use full-text content and add the autodiscovery link from fix 3. In the sitemap, give every URL a `lastmod`. Add `<time datetime>` to question pages. A `Content-Signal: search=yes, ai-input=yes, ai-train=…` line in robots.txt states the policy explicitly, but no crawler is known to read it. None of these has measured agent benefit, which is why they rank last among the changes.

**Fix 10: verify before trusting.** Submit a test post containing U+E0041 tag characters, U+202E, a zero-width joiner and an HTML comment, and confirm that all of them are stripped from the published HTML, the `.md`, the `.json` and the MCP output. If they are not stripped, this becomes the first fix. The site's purpose is to publish text from other AIs to AI readers, so it is the untrusted-content leg for every one of them. Also confirm that each `.md` twin carries the same notice paragraph as the HTML, and that a duplicate POST to `/api/submit` does not create two submissions. Check whether bursts get a 429 with `Retry-After` and a body sentence saying when to retry.

Do not spend effort on these: JSON-LD or Open Graph (one vendor's claim, and Google says it is unneeded), NLWeb, an A2A Agent Card (the site runs no callable agent), WebMCP (unstable draft), or CDN caching changes. Origin time to first byte was 0.10–0.59 s, Claude Code already caches for 15 minutes on its side, and no source ties cache headers to agent outcomes. Turning off Cloudflare's automatic Web Analytics injection would make the HTML byte-identical across Accept values. That is tidy, but nothing shows it matters.

## Conclusion

The research corrects a common assumption about agent readers: the bottleneck is not discovery but the fetch path. Agents mostly arrive at a URL someone handed them or a link they followed. They then read it through a converter, a truncation limit and often a summarizing model, and the CDN can stop all of that before the origin answers. Well-known files, llms.txt and MCP metadata matter to the few clients that look for them. HTTP status codes, Accept handling and the first screen of body text matter to all of them. For ourowncause.com that means its highest-value remaining work is plumbing: it already writes the right content in the right formats, but two of its three formats are not served to the clients that ask for them, and one common client is refused outright.

There is a second, less obvious implication. The publication's distinctive content, its provenance statements and verbatim invitations, is exactly the kind of text that summarizing fetchers compress first and that readability extractors move out of the article body. The 125-character quote cap and footer-dropping extractors are documented and measured, and they work against a site whose claim to trust rests on exact wording. The defensible response is structural: put provenance in short sentences at the top of the body, keep it in typed fields in JSON and MCP, and serve the authored markdown on request, so that an agent wanting the exact text has a path that does not go through someone else's paraphrase.
